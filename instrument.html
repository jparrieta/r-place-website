Instrument

The instrument turns the shared record of r/place into accounts that later studies can test and revise. It has three parts, run in order, each by its own handler: collection, community coding and aggregation. Each part takes the one before it as input and works under its own written instructions. The section has a page for each part, then Versions and Run the study.

Collection

Gathers the public record once, then hashes and freezes every file. Scripts collect; the census judgments are ours.

  1. 1 The pixel record

    Reddit's log of all 16,559,897 pixel changes, each with the placer's hashed name.

  2. 2 The atlas

    The 1,473 artworks of the finished canvas, their outlines and the subreddits they name.

  3. 3 What was written

    Everything the placers wrote on Reddit in the 24 days around the canvas, and everything anyone wrote in 24,093 subreddits in those days.

  4. 4 Pixels by artwork and by hour

    Every pixel change inside each artwork's outline, and each community's area hour by hour.

  5. 5 The census

    Which of the 2,796 subreddits in the wider dataset count as cases: 705 communities.

Community coding

One community coder per community reads its whole record and writes codes, themes and a case account, close to its members' words. It sees no other community. A scheduler prepares, launches and checks each coder; fleet coders help with the largest communities.

  1. 1 The briefing

    A brief writer's account of the community's ordinary week before the event, read for orientation; a claim with no quote behind it counts as unsupported.

  2. 2 Every thread

    The coder goes through the record in time order and decides, thread by thread, whether it touches the event; a thread that does is read in full.

  3. 3 First-order codes

    One code per passage, close to the members' words and tied to its quote.

  4. 4 Themes

    The coder groups the codes into second-order themes by asking what these people are doing; each code sits in one theme.

  5. 5 The case account

    The chronology, what set off what, posts against comments, a counter-reading and saturation, each resting on the codes.

Aggregation

The aggregator reads the coders' sealed work, never the record. Over eighteen stages in six groups it builds layers of themes and one population model, returns the model to every community coder, revises it, and groups the communities into candidate organizational forms.

  1. 1 Reading, A1

    A note on each community before any common scheme is named.

  2. 2 Coding, B1 to B4

    A scheme of 197 third-order themes, tested by fresh readers, applied to all 7,844 second-order themes and settled where readers disagreed.

  3. 3 Model, C1 to C5

    28 fourth-order themes, eight aggregate dimensions and the population model with its account.

  4. 4 Adaptation, D1 to D3

    The model goes back to every community coder; the aggregator rules on each change and revises the model.

  5. 5 Forming, D4 to D6

    Communities that asked for similar changes form six candidate organizational forms; each form gets an account, and the model is retold with the forms inside it.

  6. 6 Formalizing, E1 and E2

    An audit of what the run supports, and a review of how the run was handled and what the next instrument should change.
