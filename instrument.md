# Instrument

The instrument turns the shared record of r/place into accounts that later studies can test and revise. It has three parts, run in order, each by its own handler: collection, community coding and aggregation. Each part takes the one before it as input and works under its own written instructions. The section has a page for each part, then Versions and Run the study.

## Collection

Gathers the public record once, then hashes and freezes every file. Scripts collect; the census judgments are ours.

- [The pixel record](sources/data-pixels.html): Reddit's log of all 16,559,897 pixel changes, each with the placer's hashed name.
- [The atlas](sources/data-atlas.html): the 1,473 artworks of the finished canvas, their outlines and the subreddits they name.
- [What was written](how-collection-works.html#the-steps): everything the placers wrote on Reddit in the 24 days around the canvas, and everything anyone wrote in 24,093 subreddits in those days.
- [Pixels by artwork and by hour](sources/data-pixels-per-artwork.html): every pixel change inside each artwork's outline, and each community's area hour by hour.
- [The census](results/population-record.html#census): which of the 2,796 subreddits in the wider dataset count as cases: 705 communities.

## Community coding

One community coder per community reads its whole record and writes codes, themes and a case account, close to its members' words. It sees no other community. A scheduler prepares, launches and checks each coder; fleet coders help with the largest communities.

- [The briefing](sources/coder-contract.html#4-step-1--the-briefing): a brief writer's account of the community's ordinary week before the event, read for orientation; a claim with no quote behind it counts as unsupported.
- [Every thread](sources/coder-contract.html#5-step-2--go-through-every-thread-and-decide-what-this-case-is): the coder goes through the record in time order and decides, thread by thread, whether it touches the event; a thread that does is read in full.
- [First-order codes](sources/coder-contract.html#6-step-3--first-order-codes): one code per passage, close to the members' words and tied to its quote.
- [Themes](sources/coder-contract.html#7-step-4--themes): the coder groups the codes into second-order themes by asking what these people are doing; each code sits in one theme.
- [The case account](sources/coder-contract.html#8-step-5--the-within-case-account): the chronology, what set off what, posts against comments, a counter-reading and saturation, each resting on the codes.

[Community coding](how-coding-works.html) · [What it gave: community coding](results/population-coding.html)

## Aggregation

The aggregator reads the coders' sealed work, never the record. Over eighteen stages in six groups it builds layers of themes and one population model, returns the model to every community coder, revises it, and groups the communities into candidate organizational forms.

- [Reading, A1](how-it-works.html#group-reading): a note on each community before any common scheme is named.
- [Coding, B1 to B4](how-it-works.html#group-coding): a scheme of 197 third-order themes, tested by fresh readers, applied to all 7,844 second-order themes and settled where readers disagreed.
- [Model, C1 to C5](how-it-works.html#group-model): 28 fourth-order themes, eight aggregate dimensions and the population model with its account.
- [Adaptation, D1 to D3](how-it-works.html#group-adaptation): the model goes back to every community coder; the aggregator rules on each change and revises the model.
- [Forming, D4 to D6](how-it-works.html#group-forming): communities that asked for similar changes form six candidate organizational forms; each form gets an account, and the model is retold with the forms inside it.
- [Formalizing, E1 and E2](how-it-works.html#group-formalizing): an audit of what the run supports, and a review of how the run was handled and what the next instrument should change.
