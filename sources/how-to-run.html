How to run the tools, v43

Everything works from inside the folder you were given. Nothing reaches outside it. Read this once, at stage A1. Tools marked new do not exist in v37 and are built before the run (CHANGELOG-v37-to-v38.md, "Not yet done").

Every call is logged to out/_mem_reads-NN.jsonl (NN from --stage, else the .stage file the harness writes at every hand-over). Pages are 80 lines; --offset and --limit page through. Placements, fourth-order themes, dimensions and elements are overlaid from out/ at query time.

The fleet's pages

python3 tools/packets.py B2|B3 --scheme out/scheme_final.jsonl --families out/families.jsonl \
        --to out/_packets-NN [--exemplars]
python3 tools/handoff.py D --verdict-only     # the verdict packets alone, from the frozen MODEL-D1.md and model/

The index page, one file per family, a batch's themes with their sibling block; 50 KB ceiling asserted, end marker appended. The dispatch (FLEET.md) is the operator's fleet.py, not yours.

Open, close, cut, views

python3 tools/validate.py --open NN          # startup counts; fails on an unresolved link
python3 tools/validate.py NN                 # the close-check; refuses by name what it cannot check
python3 tools/validate.py --links            # new: every id in head, questions, views resolves
python3 tools/validate.py --self-test        # once, at A1
python3 tools/gen_views.py NN                # new: _views/ and _wiki/ regenerated, hashed
bash tools/done.sh NN [--cut <name>]         # new: close-check, views, snap, tokens, probe, session id
python3 tools/snap.py NN move-<move>-<n>     # a move's snap, taken when the move is made; the leg stays open
python3 tools/counts.py . out/               # the denominators; run it, never read the copy

done.sh is the leg's one exit. It runs the close-check, the links check and gen_views.py, and marks the leg closed. Then stop: what happens next (the snap, the recall probe in a fork of your session, the checkpoint) is your platform's, and your platform file says how.

Your platform

The instrument runs on two platforms, Claude and Codex (since v41). Everything in this folder is the same on both but two files: PLATFORM-claude.md and PLATFORM-codex.md name the models, the efforts, the reader routes and how a leg is opened, closed, paused and compacted. Read yours (CLAUDE.md points Claude to its own, AGENTS.md points Codex to its own).

  • Legs. Every stage is legs; fleet stages are build, dispatch, check; C2 to C5 one leg per pass, every move logged and snapped as it is made; D3 one leg per element group. Each ordinary leg continues the previous leg's conversation from its committed checkpoint, in the same folder; the startup packet (the standing instructions') orients that continuation and does not replace it.
  • _head.md is at most 3,000 words, rewritten at every close and before every cut.
  • Three limits of the runner. A tool result can be clipped without saying so above a fixed size: page long files. A shell call past its timeout is killed: run long scripts in the background with output to a file. Nothing in out/ is deleted.
  • Forks. The operator may fork the run at a stage boundary (after A1, after C1, after C5, and at any cut). You are not told you are a fork; the carried fork is chosen by the rule in RUN.json, declared before any fork ran.
