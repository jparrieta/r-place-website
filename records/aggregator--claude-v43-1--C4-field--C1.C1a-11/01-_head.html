The method question, in one sentence

Can independently reconstructed case histories be composed into a shared dynamic account that supports explanations at successive levels of specificity, from population-wide patterns, through forms and subforms, to particular organizational histories, while keeping access to the evidence from which those explanations were developed?

The theory question is unchanged: when strangers organize on a clock they did not set, with no way to compel anyone and no goal given to them, what forms does organizing take, how do they differ in their functioning, and which of them keep the work alive?

Rules kept

  • Never type an id, an order or a name from memory; check with a script. Never log a write before the tool answers. Count a ledger's lines after appending. A claim about a ledger in a handback is checked against the ledger before it is logged.
  • There is no --kind close and no --kind episode; log those as notes.
  • A question to J is mem.py ask "<question>" --assume "<meanwhile>". Read an answer with mem.py asks <id>.
  • Never put a placeholder or a no-op in a command or a log line. Never put an Edit or Write and the read, dry run or validator run that checks it in one turn. Count the head's words before the closing line.
  • Never write an id-like token the run does not define in the head, such as a D or a P followed by digits, or a form-pass id: done.sh reads it as an unresolved link.
  • The permission check refuses: shell variables set and expanded in a command; shell loops and words beginning "for_" (an inline Python line starting with "for" included); shell functions, brace groups and heredocs; awk with system() or $ fields; env-var prefixes; cat or jq on out/diary/; cut -c anywhere in a command that also runs mem.py, cite.py or a helper, or greps the helpers (use --width, the Read tool's line ranges, or grep -o with bounded context); head -n -N. Write a script file in out/_analysis/ instead. .git is read-denied, and so are reads outside the run folder, the system's temporary folder included.
  • mem.py pages long output (--offset). A Read above about 25,000 tokens is refused; page by about 330 lines. Set timeout up to 600000 for long writes.
  • After a compaction the guard requires the head and stage file read again, after the compaction notice, and the exact line "compacted; head reconciled" through mem.py log --kind note, in a call of its own, before any other step.
  • Never delete a file; supersede it with a new name. A generated document that must keep its name is corrected in place with Edit, and the script that wrote it is fixed too.
